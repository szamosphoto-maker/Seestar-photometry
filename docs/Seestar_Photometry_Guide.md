# Seestar Photometry – Exploring Variable Stars Beyond the Main Target

### A free Windows application for processing Seestar photometric measurements

**By Zsolt Szamosvári**

## Introduction

Modern smart telescopes have made astronomical observation more accessible than ever. With instruments such as the Seestar S50, amateur astronomers can photograph deep-sky objects, observe the Sun, and now perform photometric measurements of variable stars.

The introduction of photometry into the Seestar software opened up an interesting new opportunity. During my first experiments with eclipsing binary stars, I began investigating the measurement CSV files generated by the telescope.

I soon discovered something particularly useful: these files contain considerably more information than just measurements of the selected target star.

They also include photometric measurements of many other stars in the field of view, including stars flagged as variables.

This raised a question: **Why limit the analysis to the main target when the telescope has already measured other potentially interesting variable stars?**

To explore this possibility, I developed **Seestar Photometry**, a Python-based processing application specifically designed for Seestar measurement CSV files.

After several weeks of testing with real observations, the software is now available as a standalone Windows application, requiring no Python installation.

---

## 1. More information hidden in Seestar CSV files

When Seestar performs photometric observations, it generates measurement CSV files containing information about stars detected in the observed field.

These files may include stellar coordinates, measured magnitudes, magnitude errors, signal-to-noise ratios, observation times, and other photometric parameters.

One particularly interesting column is:

**Is Variable**

This field identifies stars marked as variables in the Seestar measurement data.

Instead of processing only the dedicated target's photometry export, Seestar Photometry works directly with these measurement CSV files.

This provides two important possibilities:

First, the program can extract and combine repeated measurements of a selected variable star, including observations from several nights.

Second, it can search the entire set of measurements for other stars flagged as variable and attempt to identify them using the AAVSO International Variable Star Index (VSX).

In this way, a single observing session may provide useful light curves for several variable stars, not just the originally selected target.

However, there is an important limitation. Seestar uses an alt-azimuth mount, and field rotation causes surrounding stars to move through the observed field. Secondary variables may therefore appear in the measurement data for only part of an observing session.

Consequently, their light curves may be incomplete, even when the main target has been followed continuously.

Nevertheless, these measurements can still reveal interesting brightness variations.

## 2. The Seestar Photometry interface

The application was designed to be straightforward to use, even for observers without programming experience.

After starting the program, the user selects the folder containing Seestar measurement CSV files.

Only CSV files directly inside the selected folder are processed. Subfolders are not searched automatically.

The interface offers two analysis modes:

**Target Star** and **All Variables**.

The program also includes tools for managing variable star information and defining the observer's geographical location.

## 3. Target Star mode – detailed analysis of a selected variable

Target Star mode is intended for the analysis of a specific variable star.

The user selects an existing variable star card containing the necessary catalogue information and ephemeris parameters.

The software then searches the measurement CSV files for observations corresponding to that star.

Matching uses stellar coordinates, including proper-motion information when available.

Measurements from different nights can be combined into a single dataset. This is particularly useful for eclipsing binaries whose orbital periods cannot be covered completely during one observing session.

The program produces three different light curves.

### Time Curve

The Time Curve displays the measured brightness as a function of observation time.

It is useful for examining the actual observing sequence, identifying eclipses, and comparing measurements from different nights.

The program can also display a running median to make the underlying brightness variation easier to follow.

### Raw Curve

The Raw Curve shows the original measured magnitudes without applying the program's photometric quality or spike filtering.

This is especially useful for identifying outliers, observing interruptions, and other unusual features in the measurements.

### Phase Curve

The Phase Curve combines observations according to the variable star's period and reference epoch.

The phase is calculated using:

\[
\phi=\operatorname{frac}\left(\frac{HJD-T_0}{P}\right)
\]

where HJD is the heliocentric Julian Date, T0 is the reference epoch, and P is the period in days.

By folding measurements from several nights into one orbital cycle, it becomes possible to reconstruct parts of a light curve that could not be observed continuously during a single night.

The software also applies quality checks based on photometric errors and signal-to-noise ratios. Suspected short-lived brightness spikes are excluded from cleaned measurements but retained for inspection.

## 4. Variable Star Cards – managing catalogue information

To create Phase, Time, and Raw curves in Target Star mode, the program uses a simple system of variable star cards.

Each card is stored as a text file and contains the parameters needed to identify and analyse the variable star.

These include the variable star name, coordinates, Gaia DR3 information when available, proper motion, variability type, period, and reference epoch.

Additional information, such as the magnitude range and eclipse duration, may also be included.

The **Variable Card Manager** allows users to create, inspect, and save these cards through a graphical interface.

There is no need to edit text files manually.

### Automatic catalogue lookup

The program can examine the CSV file and suggest stars marked as variable.

The user can browse these candidates and request catalogue information using the VSX Search function.

Where available, the software retrieves the name, type, period, epoch, magnitude information, and other relevant parameters. Gaia data can provide additional astrometric information.

This considerably reduces the amount of manual data entry.

### Why must T0 be verified?

The reference epoch is essential for correctly calculating a phase curve.

Catalogue epochs may be old, uncertain, or affected by subsequent period changes.

For example, an epoch published several decades ago may no longer predict the exact time of an eclipse if the orbital period has changed.

The program therefore treats a catalogue T0 value as a proposed value that must be checked before the card is saved.

Predicted events listed in VSX ephemeris tables should not automatically be interpreted as newly observed minima.

Once a card has been verified and saved, it can be reused for future observing sessions.

This is especially convenient when following a variable star over several nights or weeks.

## 5. Observatory Settings – observing from anywhere

Accurate timing is an important part of variable star photometry.

To account for the changing position of the Earth relative to the Sun, the software calculates a heliocentric time correction for Target Star phase analysis.

The observer's location is therefore configurable.

In the Observatory Settings window, users can specify their observatory name, geographical latitude, longitude, and elevation above sea level.

**[Figure 3 – Observatory Settings]**

*Figure 3. The Observatory Settings window. Geographical coordinates are saved locally and used when calculating heliocentric observation times.*

The settings are saved and automatically reused during subsequent sessions.

The program is not restricted to my own observing location in Esztergom, Hungary. It can be configured for observers elsewhere in the world.

The application reads the input measurements, matches the selected star, checks photometric quality, and generates the corresponding outputs.

The processing log provides information about the number of CSV files, matched observations, accepted measurements, rejected spikes, and potential errors.

## 7. All Variables mode – discovering additional light curves

Perhaps the most interesting feature of Seestar Photometry is its second processing mode.

**All Variables** searches the measurement CSV files for stars marked as variable by Seestar.

The software groups repeated measurements according to stellar coordinates and attempts to identify the objects using the AAVSO VSX catalogue.

When a unique catalogue match is found, the variable's name and available type information are included in the output.

If an identification is unavailable or uncertain, the software can retain a coordinate-based identifier.

Users can specify the VSX search radius and the minimum number of acceptable photometric measurements.

The default VSX search radius is 8 arcseconds, although this can be adjusted.

For each qualifying variable, the program produces an individual **Time Curve**, with an optional running median.

Unlike Target Star mode, All Variables does not create Phase or Raw curves.

This distinction is intentional: individual objects discovered within the field may have incomplete coverage, and their ephemeris parameters have not necessarily been verified.

### An example from the SW Lac field

During the analysis of an SW Lac observing sequence, the program generated Time Curves for 13 objects.

Some were identified by their familiar variable-star names, while others retained Gaia-based identifiers.

This illustrates how much additional information can be recovered from a field initially observed for just one target.

**[Figure 6 – All Variables results]**

*Figure 6. The All_Variables output folder containing 13 individual Time Curves and a summary CSV file. The plots include catalogue-identified variables and objects retained under Gaia identifiers.*

It is important to remember that a star marked as variable in the measurement data is not automatically proof of genuine variability in that particular observing session.

The resulting light curves must be inspected carefully, and catalogue identifications should be verified where necessary.

Nevertheless, this mode can be a useful starting point for selecting future dedicated observing targets.

## 8. Practical example: PV Cas

One of my most interesting recent projects involved PV Cas, an eclipsing binary in Cassiopeia.

Its orbital period is approximately 1.75047 days, making it impossible to follow a complete orbital cycle during a single observing night.

I therefore collected observations over four nights and combined them using Seestar Photometry.

The resulting phase-folded light curve shows a well-defined primary eclipse, together with other portions of the orbital brightness variation.

**[Figure 7 – PV Cas Phase Curve]**

*Figure 7. Phase-folded light curve of PV Cas obtained with the Seestar S50. Measurements from four observing nights were combined using a period of approximately 1.75047 days. Point colours indicate the estimated magnitude errors, while rejected spikes are displayed in grey.*

This example demonstrates one of the main advantages of processing data from multiple sessions: observations recorded on different nights can be combined to reconstruct a more complete view of a periodic variable star.

The result also illustrates the importance of checking the adopted period and reference epoch. Even a small timing error can produce noticeable phase shifts when observations are folded over many orbital cycles.

## 9. Practical example: SW Lac

Another successful observing session targeted SW Lac, a short-period eclipsing binary in Lacerta.

On October 18, 2026, I recorded a continuous observing sequence lasting approximately 5.51 hours.

The dataset contained 1,748 accepted photometric measurements.

The resulting Time Curve clearly displays the changing brightness of the system, including two eclipses of different depths.

**[Figure 8 – SW Lac Time Curve]**

*Figure 8. Time-series light curve of SW Lac observed on October 18, 2026. The 5.51-hour session produced 1,748 accepted measurements. Blue points represent the measurements, and the orange line shows the optional running median.*

The median reported magnitude error was approximately 0.082 mag, while the median signal-to-noise ratio was about 246.

This example demonstrates that Seestar measurement data can contain enough temporal detail to follow substantial brightness variations over a single observing session.

Of course, the results should be interpreted with appropriate caution. Instrumental effects, atmospheric conditions, measurement uncertainties, and systematic errors can all influence the recorded magnitudes.

The photometric precision and scientific suitability of any particular dataset must be evaluated individually.

## 10. What the software does – and does not do

Seestar Photometry is a post-processing application.

It does not perform independent aperture photometry on astronomical images or replace the Seestar measurement process.

Instead, it takes the photometric measurements already produced by the telescope and makes them easier to analyse, organise, visualise, and compare.

Its main benefits are the ability to combine observations from several nights, construct phase-folded light curves, examine original and cleaned measurements, and extract additional variable-star light curves from the observed field.

The program is primarily intended as a practical tool for amateur astronomers exploring variable star photometry with Seestar smart telescopes.

The resulting light curves can be valuable for learning, experimentation, and identifying promising observing targets. Further validation and calibration may be required before using them for precision scientific measurements.

## 11. Download and installation

Seestar Photometry is available as a free standalone Windows application.

No Python installation or programming knowledge is required.

To begin, download the software, extract the archive, and launch the executable file.

On the first run, enter your observing location in Observatory Settings.

Then select a folder containing Seestar measurement CSV files.

For Target Star analysis, select an existing variable star card or create a new one using the Variable Card Manager.

For a broader survey of the observed field, choose All Variables.

The program will save its results automatically in the Results folder.
